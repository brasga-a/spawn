# ADR-0014 — Shader Toolchain Integration

**Status:** Accepted  
**Scope:** How Slang shaders ([ADR-0004](0004-in-house-graphics-api.md)) are compiled, versioned, loaded and hot-reloaded.  
**Related:** [ADR-0015](0015-asset-pipeline.md) (asset pipeline), [ADR-0007](0007-toolchain-lints-and-ci.md) (CI).

## Context

ADR-0004 chose Slang compiled offline to SPIR-V and deferred how the compiler is installed and invoked. Shader compilation must not make every `cargo build` (including headless crates and CI jobs without GPU) depend on an external compiler.

## Decision

1. **Compilation is an asset-pipeline step, not `build.rs`.** `spawn-cli` provides a command (e.g. `spawn shaders build`) that invokes `slangc` and writes SPIR-V plus reflection data to the build output. `build.rs` scripts never call `slangc`.
2. **Pinned compiler version:** the required Slang version is recorded in the repository; `spawn-cli` checks the installed `slangc` version and fails with a clear message on mismatch.
3. **Generated SPIR-V is not committed.** It is a build artifact, regenerated by the pipeline; CI installs the pinned `slangc` only in jobs that need shaders.
4. **Reflection data:** binding layouts, push-constant layouts and vertex inputs are taken from Slang's reflection output and validated by `spawn-render` against what the RHI expects; mismatches are load errors, not GPU faults.
5. **Hot reload (development):** a file watcher (in `spawn-cli` or the editor) recompiles changed shaders; `spawn-render` swaps pipelines at a frame boundary and keeps the previous pipeline on compilation failure.
6. **Shader variants:** permutations are explicit and enumerated, never generated combinatorially without a budget.
7. **Runtime never compiles shaders** from source in shipping builds; it loads cooked SPIR-V. Pipeline caches (Vulkan pipeline cache) are stored per machine.

## Alternatives

- **`build.rs` invoking `slangc`:** automatic, but forces the compiler on every build and every CI job; rejected.
- **Runtime compilation via the Slang library:** flexible hot reload; adds a large native dependency to the engine runtime; acceptable only for development tools, never shipping builds.
- **Committing SPIR-V:** builds without `slangc`; binary churn in version control and stale-artifact risk.

## Consequences

- Rendering development requires `slangc` installed locally (not currently installed on the reference machine).
- `spawn-cli` gets its first real responsibility.

## Risks

- **Toolchain drift** between developers and CI. Mitigation: version check in `spawn-cli`.
- **Driver pipeline compilation stutter** when pipelines are first created. Mitigation: pipeline cache and pre-creation at load time; measured on the reference hardware.
- **Slang license:** verified under [ADR-0008](0008-third-party-license-policy.md) as `Apache-2.0 WITH LLVM-exception` (permissive, no royalties or copyleft; development-only external compiler).

## Revisit triggers

Hot reload latency is too high; variants grow beyond the budget; a D3D12 backend is added (DXIL output).

## Acceptance conditions

Accepted by owner review before the first shader (`Apache-2.0 WITH LLVM-exception` license verified).

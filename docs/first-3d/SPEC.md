# Specification — First 3D Rendering and Free Camera

**Status:** `PLANNED`. Items depending on *Proposed* [ADR-0014](../adr/0014-shader-toolchain.md), [ADR-0020](../adr/0020-memory-strategy.md), or [ADR-0022](../adr/0022-repository-layout.md) are marked **proposal (pending Phase 0 owner acceptance)** and must not be implemented before owner sign-off ([PLAN.md](PLAN.md#ordered-increments)).  
**Audience:** contributors implementing `spawn-math`, `spawn-cli`, `spawn-render`, and the root `spawn-engine` executable.

## Goal

Deliver a minimal, genre-independent 3D vertical slice on top of the [Foundation runtime](../foundation/SPEC.md): establish Spawn's engine-wide spatial math and `f64` world-coordinate conventions (`spawn-math`), compile Slang shaders offline to SPIR-V with reflection validation (`spawn-cli` → `spawn-render`, *proposal per ADR-0014*), allocate and synchronize GPU buffers, depth attachments, and Vulkan 1.3 dynamic-rendering pipelines (`spawn-render`), and navigate a procedural 3D test scene with a 60 Hz fixed-step `f64` free-fly camera rendered through `alpha`-interpolated, camera-relative `f32` transforms (`spawn-engine`).

This milestone is **not** a scene graph, ECS renderer, glTF/texture importer, PBR material system, render graph, or gameplay controller.

## Functional requirements

| ID | Requirement | Observable acceptance |
| --- | --- | --- |
| F3D-FR-01 | `spawn-math` provides in-house `Copy` types for `f32` local math (`Vec2`, `Vec3`, `Vec4`, `Mat3`, `Mat4`, `Quat`, `Transform`, `Aabb`, `Ray`, `Plane`, `Sphere`) and distinct `f64` world-position types, following right-handed, Y-up, −Z forward, column-major (`M * v`), radian conventions and explicit `f64` ↔ `f32` camera-relative conversions ([ADR-0010](../adr/0010-math-library.md)). | Headless unit, `proptest` algebraic-law, `glam` oracle, and degenerate-input tests (`F3D-T01`, `F3D-T03`) pass without panics. |
| F3D-FR-02 | `spawn-math` constructs reversed-Z perspective projections for Vulkan `[0, 1]` clip depth (`near` → `1.0`, `far` → `0.0`, finite and infinite-far variants) and applies the Vulkan NDC Y-flip in one documented place without inverting front-face screen winding ([ADR-0010](../adr/0010-math-library.md)). | Headless projection/winding tests and GPU depth/occlusion readback (`F3D-T02`, `F3D-T12`) confirm depth mapping, axis signs, and counter-clockwise front-face consistency. |
| F3D-FR-03 | `spawn-math` exposes an explicit deterministic `f32`/`f64` subset (IEEE `sqrt` and pure-Rust `libm` wrappers for `sin`, `cos`, `sin_cos`, `atan2`, clamped inverse trig, `exp`, `ln`, with explicit FMA rules) distinct from fast presentation math ([ADR-0010](../adr/0010-math-library.md)). | Recorded golden-vector and deterministic simulation-camera tests (`F3D-T04`, `F3D-T05`) produce bit-identical results across runs and across Linux and Windows CI. |
| F3D-FR-04 | **Proposal (pending Phase 0 acceptance of [ADR-0014](../adr/0014-shader-toolchain.md)):** `spawn-cli` provides a non-interactive shader build command (e.g. `spawn shaders build`) that verifies the pinned `slangc` version, compiles `.slang` sources offline to Vulkan 1.3 SPIR-V plus reflection metadata into uncommitted build output, and reports located errors and exit codes without using `build.rs`. | Headless mock-compiler CLI tests and opt-in pinned-`slangc` integration tests (`F3D-T06`) verify version checks, artifact generation, and diagnostics. |
| F3D-FR-05 | `spawn-render` loads cooked SPIR-V + reflection artifacts (**reflection sidecar contract proposal per [ADR-0014](../adr/0014-shader-toolchain.md)**) and validates headers, 4-byte SPIR-V alignment, size bounds, entry points, vertex attributes, descriptor bindings, and push-constant ranges against RHI pipeline descriptors before GPU object creation. | Headless parser/validation tests and fuzzing (`F3D-T07`) reject corrupt, truncated, oversized, or mismatched shader artifacts with typed `RenderError`s (`REND-0010`+). |
| F3D-FR-06 | `spawn-render`'s private Vulkan 1.3 RHI implements an in-house block/suballocation GPU memory allocator ([ADR-0004](../adr/0004-in-house-graphics-api.md)) supporting device-local vertex, index, and depth memory plus host-visible staging uploads, timeline-semaphore-gated retirement of in-flight resources, and leak-free shutdown. | Headless allocator bookkeeping tests (`F3D-T08`) and opt-in Vulkan validation tests (`F3D-T11`, `F3D-T12`) verify alignment, reuse, safe retirement, and zero leaked blocks. |
| F3D-FR-07 | `spawn-render` creates and manages a swapchain-sized `VK_FORMAT_D32_SFLOAT` depth image and view configured for reversed-Z (`clear = 0.0`, `VK_COMPARE_OP_GREATER_OR_EQUAL`, depth write enabled), recreating it across swapchain resize/recovery, suspending cleanly at `0x0` extent, and ordering transitions via `synchronization2`. | Headless attachment state tests (`F3D-T09`) and opt-in GPU resize/readback tests (`F3D-T12`) pass with zero validation errors. |
| F3D-FR-08 | `spawn-render` executes Vulkan 1.3 `dynamicRendering` graphics pipelines (no `VkRenderPass` or `VkFramebuffer`) with push-constant or descriptor-indexed transforms, supporting both an unindexed colored triangle pass and indexed 3D mesh draws with counter-clockwise front faces and backface culling. | Opt-in GPU offscreen-readback and headless-surface swapchain draw tests (`F3D-T11`, `F3D-T12`) confirm expected triangle pixels, reversed-Z occlusion across overlapping 3D meshes, and clean swapchain presentation. |
| F3D-FR-09 | `spawn-engine` steps a genre-free free-fly camera on the fixed 60 Hz `FixedStepClock` schedule using `f64` world position, radian yaw/pitch (pitch clamped away from `±π/2`) integrated via `spawn-math`'s deterministic subset, and `spawn-input` `InputCommand`s (3 digital translation axes, unaccelerated relative pointer look axes, cursor-lock toggle). | Headless camera simulation and session tests (`F3D-T05`, `F3D-T10`) prove identical tick poses across non-dropping render cadences, bounded catch-up clamping under backlog drops, pole safety, cursor-lock handling, and focus-loss input reset behavior. |
| F3D-FR-10 | Before rendering each frame, `spawn-engine` computes `alpha ∈ [0.0, 1.0)` from the clock's sub-tick remainder (`pending() / tick_duration()`), interpolates previous and current simulation camera poses into presentation state without mutating simulation state, and computes `(mesh_world_f64 - camera_eye_f64)` in `f64` before explicit conversion to `f32` for GPU submission. | Headless `±50 km` precision, `alpha` interpolation, session extraction, and GPU `±50 km` readback tests (`F3D-T03`, `F3D-T05`, `F3D-T10`, `F3D-T12`) verify `alpha` bounds, immutable simulation state, and sub-millimeter camera-relative accuracy. |
| F3D-FR-11 | On supported native platforms (Linux/Wayland + Vulkan 1.3), `spawn-engine` renders a procedural 3D test scene (multiple colored/shaded 3D meshes at near and far distances plus spatial reference geometry, requiring zero external mesh/texture files), navigable interactively with resize, zero-size suspension, cursor grab/release, and orderly close. | Headless 3D session verification (`F3D-T10`) and a recorded manual smoke test on the reference hardware ([VERIFICATION.md](VERIFICATION.md#manual-smoke-tests-record-environment)) confirm interactive 3D navigation, occlusion, resize recovery, and clean exit. |
| F3D-FR-12 | Every new fallible operation across `spawn-math` (if any), `spawn-cli`, `spawn-render`, and `spawn-engine` returns a hand-written typed error carrying `#[track_caller]` origin, stable code (`MATH-*`, `CLI-*`, `REND-0010`+, `ENGN-0008`+), and cause chain ([ADR-0009](../adr/0009-error-handling-and-diagnostics.md)), unwinding partially initialized CPU/GPU state in reverse ownership order. | Headless error-injection, report-snapshot, and unwind tests (`F3D-T06`, `F3D-T07`, `F3D-T08`, `F3D-T10`) plus negative smoke probes confirm diagnostics and leak-free cleanup. |

## Non-functional requirements

| ID | Requirement | Verification |
| --- | --- | --- |
| F3D-NFR-01 | Generic infrastructure (`spawn-math`, `spawn-cli`, `spawn-render`, and the `spawn-engine` free-fly camera) contains zero genre-specific concepts, types, or movement rules (no weapon, health, team, vehicle, match, or character-controller logic). | Automated symbol/API audit (`F3D-T13`) and code review. |
| F3D-NFR-02 | Crate dependencies stay downward and acyclic: `spawn-math` and `spawn-core` have zero `spawn-*` dependencies; `spawn-render` depends on `spawn-math` only (never `spawn-platform`, `spawn-input`, `spawn-core`, or `spawn-cli`); engine crates never depend on `tools/*`; headless builds pull zero windowing or GPU libraries. | Automated `cargo metadata` / `cargo tree` test (`F3D-T13`) and `./scripts/check.sh`. |
| F3D-NFR-03 | Every third-party dependency is approved for its target package in [DEPENDENCIES.md](../DEPENDENCIES.md) (`libm`, `bytemuck`, `glam` test oracle, `proptest`, `insta`, `clap`, `rspirv`, `cargo-fuzz`/`arbitrary`; external `slangc` gated on Phase 0 license sign-off). | F3D-NFR-04 | `cargo test --workspace` and `./scripts/check.sh` succeed without `slangc`, a display server, or a GPU; runtime crates never compile shaders from source, and (**proposal per [ADR-0014](../adr/0014-shader-toolchain.md)**) no `build.rs` invokes external shader compilers. | Headless CI gates (`./scripts/check.sh`), `F3D-T06`, and `F3D-T13`. |
| F3D-NFR-05 | `#![forbid(unsafe_code)]` holds in `spawn-input`, `spawn-cli`, and `spawn-engine` (and `spawn-math` unless a benchmarked intrinsic is explicitly justified); all Vulkan `unsafe` calls stay inside `spawn-render/src/vulkan/` with `// SAFETY:` comments; steady-state tick and frame paths perform no unbounded or per-object heap allocations (**budget tracking proposal per [ADR-0020](../adr/0020-memory-strategy.md)**). | Clippy lints, code review, allocator accounting tests (`F3D-T08`), and manifest/attribute audit (`F3D-T13`). |
| F3D-NFR-06 | All Vulkan 1.3 paths execute with zero validation or synchronization-validation errors under `VK_LAYER_KHRONOS_validation` + `VK_KHRONOS_VALIDATION_VALIDATE_SYNC=true` on the reference hardware. | Opt-in GPU tests (`F3D-T11`, `F3D-T12`) and recorded reference-hardware smoke runs. |
| F3D-NFR-07 | Frame times, VRAM allocations, and platform support claims are stated only from recorded runs on named environments; untested platforms (Windows, X11) and untested GPUs are called out explicitly. | Status/doc consistency audit (`F3D-T13`), recorded smoke table, and exit-gate review ([VERIFICATION.md](VERIFICATION.md#exit-gate)). |

## Out of scope

- ECS entity/component storage or scheduling (`spawn-ecs`), runtime worlds (`spawn-world`), scene files (`spawn-scene`), reflection (`spawn-reflect`).
- glTF/FBX mesh importing, PNG/JPEG/EXR texture decoding, BCn compression, `.meta` UUID sidecars, runtime `spawn-assets` streaming ([ADR-0015](../adr/0015-asset-pipeline.md)).
- Lighting/PBR materials, shadow maps, post-processing, MSAA, skyboxes, text/UI (`spawn-ui`), debug-draw frameworks, or an automatic render graph with transient resource aliasing.
- Shader permutation systems, pipeline disk caches, and live file-watching shader hot reload (deferred beyond the initial offline cook slice even after [ADR-0014](../adr/0014-shader-toolchain.md) review).
- Collision detection, kinematic character controllers, gravity, or rigid-body physics (`spawn-physics`), audio (`spawn-audio`), networking (`spawn-network`), and Luau scripting (`spawn-scripting`).
- X11 and Win32 window/surface backends (`PLANNED` under [ADR-0001](../adr/0001-in-house-platform-layer.md)), async compute or dedicated transfer queues, and GPU device-loss recovery.

## Assumptions and blockers

- **Accepted binding ADRs:** [ADR-0001](../adr/0001-in-house-platform-layer.md) (platform/input capture), [ADR-0002](../adr/0002-platform-owns-raw-input-events.md) (raw event boundary), [ADR-0003](../adr/0003-fixed-step-loop-and-threading.md) (60 Hz fixed-step loop, single-threaded runtime, simulation/presentation split), [ADR-0004](../adr/0004-in-house-graphics-api.md) (Vulkan 1.3 via `ash`, private RHI, in-house GPU memory allocator, offline Slang → SPIR-V), [ADR-0007](../adr/0007-toolchain-lints-and-ci.md) (pinned Rust 1.99.1, lints, `scripts/check.sh`), [ADR-0008](../adr/0008-third-party-license-policy.md) (license rules), [ADR-0009](../adr/0009-error-handling-and-diagnostics.md) (hand-written located errors), [ADR-0010](../adr/0010-math-library.md) (`spawn-math`, spatial conventions, `f64` world positions, camera-relative `f32`, reversed-Z, single-site Y-flip, `libm` deterministic subset), and [ADR-0015](../adr/0015-asset-pipeline.md) (offline cooking in `spawn-cli`).
- **Phase 0 blocker — *Proposed* [ADR-0014](../adr/0014-shader-toolchain.md) and Slang license sign-off:** `ADR-0014` is currently `Proposed`, and `slangc` is listed as `**license to verify**` in [DEPENDENCIES.md](../DEPENDENCIES.md) ([DECISIONS.md](../architecture/DECISIONS.md#pending-decisions): *"Verify the Slang compiler license (blocks the first shader)"*). Phase 2 (`spawn-cli` shader cook) is **blocked** until the owner verifies upstream Slang's `Apache-2.0 WITH LLVM-exception` license under [ADR-0008](../adr/0008-third-party-license-policy.md), updates `DEPENDENCIES.md`, pins the `slangc` version, and accepts `ADR-0014` in [Phase 0](PLAN.md#ordered-increments). `slangc` is also not yet installed on the reference machine and must be installed for live shader cooking while keeping default CI headless and `slangc`-free.
- **Related *Proposed* ADRs (not required to start Phase 1, never silently promoted):**
  - [ADR-0020](../adr/0020-memory-strategy.md) (*Proposed*): CPU allocation patterns and subsystem VRAM budgets (~2.5 GB full-game budget on RX 460). The in-house GPU allocator itself is already authorized by accepted [ADR-0004](../adr/0004-in-house-graphics-api.md); any Milestone 2 VRAM ceiling is treated as a local engineering target (*proposal*) unless `ADR-0020` is accepted.
  - [ADR-0022](../adr/0022-repository-layout.md) (*Proposed*): standalone `examples/<name>` workspace crates. Until `ADR-0022` is accepted, Milestone 2 integrates into the existing root `spawn-engine` package (`src/` and, if needed, root `[[example]]` targets) without changing `[workspace].members`.
- **Unapproved crates notice (Gate G2):** `serde_json` and `tempfile` are **not** in [DEPENDENCIES.md](../DEPENDENCIES.md), and `blake3` is currently scoped to `spawn-assets, packages`. Implementation must either stay within already-approved crates (`clap`, `rspirv`, `std::env::temp_dir()`) or obtain explicit owner approval and update `DEPENDENCIES.md` first.
- **First smoke-test target:** Reference hardware (AMD Ryzen 5 1600, AMD Radeon RX 460 Polaris / RADV, Linux/Wayland/Hyprland, `VK_LAYER_KHRONOS_validation` + sync validation).

## Definition of done

Phase 0 owner decisions are recorded and synchronized; all automated headless tests (`F3D-T01..T10`, `F3D-T13`) pass in `./scripts/check.sh` without `slangc` or a GPU; opt-in Vulkan 1.3 GPU offscreen-readback and headless-surface presentation tests (`F3D-T11`, `F3D-T12`) pass on the reference GPU with zero Khronos validation and synchronization-validation errors; a live smoke run of `spawn-engine` with `spawn-cli`-cooked Slang shaders on the reference Linux/Wayland/Hyprland machine is recorded in [VERIFICATION.md](VERIFICATION.md); all invariants in [INVARIANTS.md](INVARIANTS.md) hold; and affected `AGENTS.md` files and `DEPENDENCIES.md` match the shipped code (`Gate G3` in [GATES.md](../architecture/GATES.md#g3--milestone-exit)).

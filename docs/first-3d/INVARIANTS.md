# Milestone 2 Invariants — First 3D and Camera

**Status:** `PLANNED` normative invariants for Milestone 2, derived from [Engine Invariants](../architecture/INVARIANTS.md) (`SPN-INV-*`) and [Foundation Invariants](../foundation/INVARIANTS.md) (`FND-INV-*`). Items marked **proposal** depend on *Proposed* [ADR-0014](../adr/0014-shader-toolchain.md) or [ADR-0020](../adr/0020-memory-strategy.md) and become binding engine-wide once accepted in [Phase 0](PLAN.md#ordered-increments); until then, no contradictory design may be implemented.

Each invariant carries a stable ID, its upstream `SPN-INV` source(s), and a concrete verification hook in [VERIFICATION.md](VERIFICATION.md).

## Failure policy

- **Recoverable:** Zero surface dimensions (`0x0` / minimized), `VK_ERROR_OUT_OF_DATE_KHR`, `VK_SUBOPTIMAL_KHR`, `VK_ERROR_SURFACE_LOST_KHR`, transient `VK_TIMEOUT`/`VK_NOT_READY` on acquire, and unsupported optional cursor-grab requests (degrade to unlocked mode with a diagnostic if cursor constraints are unavailable, or exit cleanly when explicitly required by a smoke flag). Swapchain and `D32_SFLOAT` depth attachments recreate together within existing bounded retry limits (`REND-0006` on exhaustion) without resetting `Tick` or camera simulation state.
- **Fatal (controlled unwind, nonzero exit, structured report):** Missing or corrupt cooked shader artifacts, shader reflection vs. RHI layout mismatch, GPU memory exhaustion / allocation failure, pipeline creation failure, `VK_ERROR_DEVICE_LOST` (`REND-0005`), timeline timeout (`REND-0007`), validation errors when validation is active (`ENGN-0006`), or pinned `slangc` missing/version mismatch in `spawn-cli`. Every fatal path releases already-created scene buffers/pipelines, depth views/allocations, swapchain, device, surface, and window in reverse order without panicking.
- **Logic bug / invariant violation:** Caught by unit, property, fuzz, or Khronos validation tests (`F3D-T01..T13`) and fixed at the root; never masked by silent clamping of corrupt binary headers or ignored `VkResult`s.

## Change control

Any change that modifies or relaxes an `F3D-INV-*` row must update the corresponding requirement in [SPEC.md](SPEC.md), the test case in [VERIFICATION.md](VERIFICATION.md), and — if an engine-wide rule changes — the governing ADR, [Engine Invariants](../architecture/INVARIANTS.md), [Quality Gates](../architecture/GATES.md), and affected `AGENTS.md` files in the same change (`SPN-INV-101`).
